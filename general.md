# Open Lab Challenge

## Overview

Each group draws one real data pain point, selects its own research, tool, and architecture, creates an experiment, and defends its solution with metrics. There is no starter code and no required tool; there are only a problem, constraints, and metrics.

| Item | Format |
| --- | --- |
| Groups | 6 per class |
| Topics | 7; at most two groups may share one topic |
| Independent work | 90 minutes |
| Presentation cycle | 20 minutes per group: 5 minutes presentation, 10 minutes Q&A, 5 minutes peer voting |
| Score | 100-point peer rubric plus up to 15 innovation points |

## Group Responsibilities

1. Draw a topic from the seven Data Pipeline and Governance challenges.
2. Research the pain point, establish a baseline, test a solution, and measure the primary metric.
3. Prepare at most five slides: Pain, Baseline, Solution, Evidence, Decision.
4. Present and defend the work in the 20-minute presentation cycle.

## Evaluation Integrity

Final test and evaluation cases must not be used to tune the solution. Every group must clearly describe its development/evaluation split.

## Session Timeline

| Time | Activity |
| --- | --- |
| 0:00-0:15 | Opening and topic draw |
| 0:15-1:45 | Independent work |
| 1:45-3:45 | Six presentation cycles, 20 minutes each |
| 3:45-4:00 | Winner announcement and buffer |

## Peer Rubric Summary

| Criterion | Maximum points |
| --- | ---: |
| Pain point and problem framing | 10 |
| Metric validity | 15 |
| Technical solution | 20 |
| Experiment and evidence | 25 |
| Robustness and failure analysis | 10 |
| Production feasibility | 10 |
| Presentation and Q&A | 10 |

The group with the most Best Solution votes receives a five-point bonus, capped at 100. Innovation can add up to 15 points separately.
